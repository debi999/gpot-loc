# G-POT 翻译器 · 项目说明书

> 版本 v4.0 · 2026-10-09 · 本文档随 v4.0 重设计全新编写；
> 旧版《项目说明书》（v3.5，存于旧库 indie-game-translator）冻结不再更新。

## 1. 项目定位

**G-POT 翻译器（G-POT Loc）** 是一条给独立游戏做中文化整备的桌面工具：
用户选一个游戏目录，程序识别引擎、自动部署对应的注入工具、提取待翻译文本、
调用翻译后端成批翻译，最后按引擎把译文落到游戏真正读取的位置 —— 全程不要求用户懂逆向。

设计哲学（三条铁律，从 v3.x 一脉相承）：

1. **只读红线**：不修改游戏本体文件。唯一的例外是「必须回写」类引擎
   （RPG Maker），且必须先自动备份原文、可一键还原。
2. **诚实性**：没有可靠方案的引擎如实留白（不编下载链接）；没做过的事不假装做过
   （未执行的步骤不显示编造的进度）；工具包校验状态区分「已验证 / 仅查过 API」。
3. **可回退**：原子写 + 三代备份轮转；RPG Maker 回写自动留时间戳还原点。

命名方案（2026-10-09 定稿）：

| 项 | 内容 |
|---|---|
| 中文名 | G-POT 翻译器 |
| 英文名 | G-POT Loc |
| Repo 名 | `gpot-loc` |
| Slogan | 把生肉熬成蜜语。 / Localize the desire. |
| 流程标语 | Hook · Extract · Translate. |

## 2. 业务流程（七步）

| # | 步骤 | 产出物 | 频率 | 前置 |
|---|---|---|---|---|
| 0 | 配置翻译服务 | 可用后端 + 模型列表 | 一次性 | — |
| 1 | 选择游戏目录 | 根目录 + 游戏名片 | 一次性 | — |
| 2 | 识别引擎 + 部署注入工具 | 管线方案 + 工具就位 | 一次性 | 1 |
| 3 | 提取待翻译文本 | 原文条目入库 | 游戏更新后 | 2 |
| 4 | 翻译与人工校对 | 译文（本地草稿） | 每轮迭代 | 3 |
| 5 | 保存并应用到游戏 | 游戏能读到的译文 | 每轮迭代 | 4 |
| 6 | 启动验证 / 一键还原 | 确认生效，可回滚 | 每次应用后 | 5 |

导航为**柔性规则**：可回跳已完成的步骤，不可跳前；下次打开默认落在第 4 步（高频入口）。
日常改一句台词的完整动线：点 4 → 改 → 走 5 → 重启游戏，三下。

## 3. 系统架构

### 3.1 实现架构（C 路线，M2 起已落地，2026-10-10 更新）

```
┌──────────────────────────────────────────────┐
│  UI 层  src/gpot/ui/                         │
│  七步流水线版面 FR-35~FR-52                   │
│  pywebview 宿主(host.py，frameless+WinCtl)    │
│  + 纯静态前端(assets/，只 fetch API)          │
└──────────────┬───────────────────────────────┘
               │ HTTP/JSON（唯一耦合点）
┌──────────────┴───────────────────────────────┐
│  HTTP 桥  src/gpot/api/server.py             │
│  state / providers / config / game / detect  │
│  / deploy / extract / translate / rows       │
│  / row·edit / sink / sink·apply / verify     │
│  / nav / launch / open-dir / pick-folder     │
│  / restore · APP_VERSION 版本真源             │
├──────────────────────────────────────────────┤
│  业务内核  src/gpot/core/（v3.x 血缘，原样迁移）│
│  · TranslationStore   存取/原子写/备份轮转        │
│  · Translator         8 后端/批量/缓存/护栏       │
│  · batch_fast         批量对齐通道（2.56× 提速）   │
│  · engine_detector    15 类引擎识别               │
│  · kit_catalog        工具包清单 + sink 落地真源    │
│  · kit_installer      下载/校验/部署              │
│  · rpgmaker_engine    字段白名单回写/备份/还原     │
│  · lang_detector / check_assets 等               │
└──────────────────────────────────────────────┘
```

**启动链（交付形态，FR-50/51）**：
bat（pythonw / `start /min`）→ `main.py` → 检测到自带控制台即
`CREATE_NO_WINDOW` 无窗重启自身（防黑窗；`GPOT_NOWIN=1` 防循环）→
同端口已有**同版本**实例则复用（版本比对，旧版本绕开换端口）→ pywebview 窗口。
版本唯一真源 = `server.APP_VERSION`，随 `/api/state` 下发、状态栏常显。

关键点：**内核与版面是两个变更频率完全不同的层**。v4.0 只重做 UI 层；
内核里沉淀的引擎规则、护栏判据、白名单是长期验证过的资产，原样继承。

### 3.2 按引擎分流的落地真源

`kit_catalog.sink_apply(engine)` 是「译文怎么才生效」的**唯一真源**，
UI（FR-44）必须完全由它驱动，不做通用版：

| 情形 | 判定 | 行为 |
|---|---|---|
| A 运行时替换 | `need=False`（Unity 双版本、Ren'Py） | 译文写词典；不显示「应用到游戏」「还原原文」 |
| B 必须回写 | `need=True` 且 `kind='rpgmaker'` | 先备份原文 → 字段白名单回写 `www/data/*.json`；显示「还原原文」 |
| C 无自动方案 | `need=True` 且 `kind=None` | 不显示「应用到游戏」；列出真实缺失原因；给出通用钩子退路 |

### 3.3 RPG Maker 回写的安全设计

- 字段白名单：`name` / `description` / `nickname` / `profile` / `message(s)` / `terms` 等。
- 字段黑名单（翻了会崩）：`characterName` / `faceName` / `battlerName`（图集名）、
  `switches` / `variables`（插件按名查找）、事件命令码 355/655 的 JS 脚本、注释 108、`note`。
- 备份：`<game_root>/_原文备份/data-<时间戳>/`（时间戳快照，一次性还原点）。
- 回写后全量重新 parse 断言，任一文件损坏即中止并回滚。
- 回归锁：69 项专项用例（合成 MV/MZ 工程，不碰真实游戏），restore 后要求字节级一致。

## 4. 数据与写入点

| 位置 | 内容 | 约束 |
|---|---|---|
| 翻译工作副本 | `原文=译文` 逐行（UTF-8 BOM） | 原子写 + `.bak` 三代轮转 |
| `config.ini` | 游戏目录、语言对、后端、`flow.*` 步骤状态 | 唯一用户配置入口 |
| `server_config.ini` | 本地后端参数 | 测试隔离需快照保护 |
| 导出 CSV | 人工回填 / 备份 | UTF-8-sig |
| 游戏目录 | 仅 A 情形词典 / B 情形数据文件 / 注入工具 | 见只读红线 |
| 工具缓存 | 注入工具包本地缓存（`toolcache/`，可 `ST_TOOL_CACHE` 覆盖） | 不入库 |

## 5. 关键设计决策记录（ADR 摘要）

| 决策 | 结论 | 时间 |
|---|---|---|
| 提取护栏判据 | 截断残片判据**必须限定 ASCII 码位**，写成排除法会全杀 CJK | v3.26 实证 |
| 引擎识别失败 | 剥离类型树后字节流正则 + 启发式是唯一选择；缺口（约 1,000 条长对话）如实展示 | v3.22~v3.24 |
| 「提示词长→慢」 | 伪命题；耗时≈输出长度。真杠杆是减少请求次数 + max_tokens 上限 | v3.25 实测 |
| 注入工具阶段 | 从「第 5 步保存后」**前移到第 2 步**（由引擎决定，一次性准备） | 2026-10-09 拍板 |
| 导航模式 | 柔性：可回跳、不可跳前；拒绝严格向导与双模式 | 2026-10-09 拍板 |
| 文案密度 | NFR-12：每页 ≤1 行导语；提案语言只进文档不进界面 | 2026-10-09 拍板 |
| 全量重写 | **否决**。内核资产（引擎规则/护栏/白名单/回归）是项目主要沉淀 | 2026-10-09 |
| 无边框 + 无黑窗 | pythonw 文件名不可信（本机实为控制台 shim，PE subsystem=3）；FreeConsole 在 Windows Terminal 下关不掉已显示窗口。正解 = GUI 模式带控制台即 `CREATE_NO_WINDOW` 无窗重启自身，父进程退出 | 2026-10-10 实证（v0.4.1） |
| 旧实例复用 | 必须比对 `APP_VERSION`，同版本才复用；否则「双击 bat 还是老版本」 | 2026-10-10 实证（v0.4.0） |
| 目录选择器 | 老式 SHBrowse 树形对话框被否；改 IFileOpenDialog COM 直调（Vista 现代观感，零第三方依赖），SHBrowse 仅兜底 | 2026-10-10 拍板（v0.4.3） |
| C 情形界面 | 「无方案」改「Coming soon」，选中只显示「敬请期待」，不再罗列缺失原因清单 | 2026-10-10 拍板（v0.4.3） |

## 6. 版本策略

- **v3.x（旧线）**：tkinter 界面，仓库 `indie-game-translator`，冻结。缺陷修复按需回补。
- **v4.0（本线）**：G-POT Loc，仓库 `gpot-loc`。七步版面已定稿；
  源码迁移（M2）已完成，当前处于 **v0.4.x 实测反馈迭代**（M3 功能收口）：
  v0.4.0 无边框窗口 → v0.4.1 黑窗根治 → v0.4.2 四项实测修复 → v0.4.3 七项实测修复。
  详见 [开发计划.md](开发计划.md) 迭代记录。
- 版本号规则沿旧例：EXE 命名 `GpotLoc.v4.0.exe` 式；升版本必须同步 `.bat` 版本列表与 `APP_VERSION`；
  **旧实例复用必须比对版本**（FR-51），防止双击后跑的还是旧版。

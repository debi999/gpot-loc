## 0. 美学方向（设计原则）

> **本说明书的视觉落地以 `src/gpot/ui/assets/` 的 `index.html` + `styles.css` 为准。**
> 设计由 frontend-design 技能复审、重做（2026-10-09 深夜灶台版，同日二稿）。

**定位**：Windows 桌面端的独立游戏汉化工作台。三区布局范式保留（老板已拍板），
但**拒绝"通用企业模板"观感**——浅灰底白卡片 + 一个蓝，是谁都会做的那种界面，不做。

**核心意象 · 深夜灶台（Midnight Brewing）**：产品名 **G-POT** 即一口「锅」，
口号 *把生肉熬成蜜语* 是炼制动作。整套界面就是**一台深夜里的炼制控制台**：
铸铁机身、灶火是唯一光源、步骤导航是一根发着微光的熬煮管线、等宽小字是机器的自我低语。

**四条设计铁律（与功能约束共存）**：
1. **一个光源**：蜜糖金 `#F0A93C`（灶火）是全界面唯一的高光色，决定所有主操作与强调；
   冷色（mint / 冷钢青 / 烬红）只作状态语义对照，绝不当装饰。底色是**暖调炭黑**（铸铁褐黑），
   不是程序员审美的高饱和深灰蓝。
2. **材质对比**：铸铁面板（`--surface` 渐变）+ 内嵌凹槽（输入框 `--inset` + 内阴影）
   + 灶膛暖光（左下角向内的辐射光晕）+ 极细斜纹颗粒（`.app::after`），机身有厚度，不是贴纸。
3. **动效服务于火候**：页面错落入场、卡片悬停浮起并泛金边、进度条像熬煮液面一样泛光流动、
   当前步节点脉冲、标题栏下缘一线火光明暗呼吸（`emberLine`）、锅形标记热气上升——
   全部 CSS 实现、离线可用，且**不干扰 FR-46 单主按钮 / NFR-12 密度铁律**。
4. **字体零联网**：只用 Windows 自带字体——`Bahnschrift`（DIN 工业展示体，页面大标题）
   + `Cascadia Code`（等宽标注：铭牌、徽章、指标读数、机器低语）+ `Microsoft YaHei`（正文），
   不依赖任何 CDN 字体，保证离线桌面环境一致呈现。

**字体/配色/动效的具体取值见 §1.2 视觉令牌表。**

> 注：早期版本曾定「Fluent 浅色 + 靛蓝 #4A5CD6」，实测观感仍是通用模板，已整体废弃。
> `ui_theme.py`（旧库 v3.x tkinter 主题）与 WebView2 版视觉自此脱钩，互不约束。

### 1.2 视觉令牌（深夜灶台 · 铸铁黑 + 灶火蜜糖金）

一个光源原则：蜜糖金是唯一高光色，冷色只做语义。所有取值与 `styles.css` 的 `:root` 一一对应。

| 令牌 | 值 | 用途 |
|---|---|---|
| `--amber` / `--amber-hi` | `#F0A93C` / `#FFC864` | 灶火主色：主按钮 / 当前步 / 焦点环 / 指标读数 / 悬停金边 |
| `--amber-grad` | `135° #E09422→#F0A93C→#FFC864` | 主按钮填充 / 当前置数 / 进度条液面 / 火签 |
| `--bg` / `--bg-2` | `#141210` / `#191612` | 机身底（暖炭黑，非灰）+ 灶膛暖光（`.app::before`） |
| `--surface` / `--surface-alt` | `#211D17` / `#282318` | 铸铁卡片（180° 渐变）/ 悬停与表头 |
| `--inset` | `#181510` | 内嵌凹槽：输入框 / 表格底 / 开关槽（配内阴影） |
| `--border` / `--border-str` | `#352E22` / `#4A4130` | 暖调边框 / 输入框·按钮描边 |
| `--ink` / `--text` / `--text-sub` / `--text-mute` | `#F2ECDF` / `#D8D0C0` / `#A69C88` / `#6F6759` | 暖白文字四级 |
| `--ok` / `--warn` / `--danger` / `--info` | `#5FBF7A` / `#E8B23E` / `#E06450` / `#6FA8C9` | 暗底语义色（各配 12% 透明 soft 底 + inset 辉光） |
| `--sh-1/2/3` | 黑上加黑递增投影 + `inset 1px 0 rgba(255,220,150,.04)` 顶光 | 卡片静止 / 悬停 / 浮起 |
| `--sh-amber` | `0 4px 18px rgba(240,169,60,.30)` + inset 高光 | 主按钮、当前步节点的灶火泛光 |

**圆角**：控件 6px、卡片 12px、徽章/进度条/开关 全圆（999px）。
**字体（零联网，Windows 自带）**：展示体 `Bahnschrift`（DIN 工业）→ 等宽 `Cascadia Code`（铭牌/徽章/读数）→ 中文 `Microsoft YaHei`。
**字号**：正文 14px、页面标题 30px/700（展示体）、卡片标题 15px/700、等宽标注 10~11px（大字距 `.12~.22em` 全大写）。
**动效**：页面错落入场 `pageIn/rise`、卡片悬停泛金边、进度条 `shimmer` 液面微光、
当前步节点 `markPulse` 灶火脉冲、标题栏下缘 `emberLine` 火光呼吸、锅形标记 `steam` 热气、
`logoGlow` 品牌标记明暗——全部 `@keyframes` + CSS，无 JS 业务耦合。

导航轨是一根「熬煮管线」：左侧 2px 发光导管（`steps::before`）串起全部节点，

## 3. 技术选型（**待定，不影响本规格**）

本规格是技术中立的 HTML 原型，**下面任一条路线都能实现同一份版面**：

| 路线 | 真 WinUI 3 | 保现有 Python 资产 | 相对成本 |
|---|---|---|---|
| D tkinter 重排版面 | 否 | 全保 | 最低 |
| C Python + WebView2 仿 Fluent | 否（观感接近） | 全保 | 低 |
| B C# WinUI 3 壳 + Python 内核 IPC | 是 | 全保 | 中高 |
| A C# 全量重写 | 是 | **全部丢弃** | 最高（等同重做项目） |

**不推荐 A**：Python 侧沉淀（`engine_detector` 15 类规则、`kit_catalog` 10 个工具包、
`kit_installer` 下载/校验/部署、`rpgmaker_engine` 730 行字段白名单回写、两个护栏函数、
8 个翻译后端、`run_tests.py` 447 项回归）全部要重写，且重写期间旧版仍需维护。

> **决策建议**：先按原型跑一轮观感确认版面，再据此反推哪条路线值这个钱。

## 4. 验收清单（QA 视角）

老板确认版面后，实现完成按此清单逐条验：

**流程通顺性**
- [ ] 首次打开落在第 0 步；配好后再打开默认落在第 4 步（FR-37）
- [ ] 未连通 API 时，第 4 步主按钮禁用并给出原因（FR-38）
- [ ] 未来步骤不可点击；已完成步骤可回跳且下游不清零（FR-36）
- [ ] 顶栏不再出现任何业务按钮（§2 映射表逐条核对）

**按引擎分流**
- [ ] Unity 第 5 步不显示「应用到游戏」「还原原文」，且写明「不动游戏本体」
- [ ] RPG Maker 第 5 步显示备份位置、字段白名单与黑名单，「还原原文」为危险色
- [ ] TyranoScript 第 5 步不显示「应用到游戏」，列出 ≥2 条真实缺失原因
- [ ] 上述三情形分别真机验证一次写入/回写/导出

**诚实性**
- [ ] 未执行过的步骤，副标题显示「待执行」而非编造数值
- [ ] 工具清单的校验状态区分「已验证/仅查过 API」，与 `kit_catalog.verified` 一致
- [ ] 第 3 步明示约 1,000 条长对话缺口

**交互手感**
- [ ] 路径输入框可点击、可粘贴、回车跳转、双击弹选择器（不许退回 readonly）
- [ ] 表格双击内联编辑可用；14,679 条分页滚动不卡
- [ ] 每页只有一个主按钮，文案是具体动作词

## 0. 美学方向（设计原则）

> **本说明书的视觉落地以 `src/gpot/ui/assets/` 的 `index.html` + `styles.css` 为准。**
> 设计由 frontend-design / impeccable / ui-design-languages / ui-ux-design-system 四技能定调重做（2026-10-09 炼香工坊·暧昧粉紫版）。

**定位**：Windows 桌面端的独立游戏汉化工作台。三区布局范式保留（老板已拍板），
但**拒绝"通用企业模板"观感**——浅灰底白卡片 + 一个蓝，是谁都会做的那种界面，不做。

**核心意象 · 炼香工坊（Alchemical Atelier）**：产品名 **G-POT** 即一口「锅」，
口号 *把生肉熬成蜜语* 是炼制动作。整套界面就是**一间薄暮里的炼香工坊**：
暗紫机身、玫瑰粉紫是唯一光感、步骤导航是一列发着微光的炼制试管、等宽小字是仪器的低语。
主基调贴合 R18 游戏汉化调性——暧昧的粉与紫，蜜金只留给「蜜语成品」这一语义。

**四条设计铁律（与功能约束共存）**：
1. **一个光感**：玫瑰粉 `#E8629A` 与紫 `#9B6BF0` 是全界面唯一的光源色，决定所有主操作与强调；
   蜜金 `#E8B45A` 只留给「蜜语成品 / 通过 / 已就位」这一正向语义，绝不当装饰色滥用。
   底色是**暖调深紫黑**（暗紫机身），不是高饱和深灰蓝，更不是「深色+发光霓虹」的 AI 模板味。
2. **材质对比**：绒面紫玻璃面板（`--surface` 渐变）+ 黄铜/玫瑰金描边（`--edge`）+ 内嵌凹槽（输入框 `--inset` + 内阴影）
   + 暖角辐射光晕（左上玫瑰光、右上紫光）+ 极细绒面颗粒（`.app::after`），机身有厚度，不是贴纸。
3. **动效服务于炼制**：页面错落入场（blur 交叉溶解）、卡片悬停浮起并泛粉边、进度条像炼制液面一样紫→粉渐变流动、
   当前步试管节点 `simmer` 文火脉冲、标题栏 logo 明暗呼吸——
   全部 CSS 实现、离线可用，且**不干扰 FR-46 单主按钮 / NFR-12 密度铁律**。
4. **字体零联网**：只用 Windows 自带字体——`Georgia`（衬线展示体，页面大标题，给暧昧/编辑式气质）
   + `Cascadia Code`（等宽标注：铭牌、徽章、指标读数、仪器低语）+ `Microsoft YaHei`（正文），
   不依赖任何 CDN 字体，保证离线桌面环境一致呈现。

**字体/配色/动效的具体取值见 §1.2 视觉令牌表。**

> 注：早期版本曾定「Fluent 浅色 + 靛蓝 #4A5CD6」，实测观感仍是通用模板，已整体废弃。
> 2026-10-09 又定过「深夜灶台（暖金 #F0A93C + 炭黑）」，仍被判定为「深色+发光」AI 模板味，现已改为「炼香工坊（暧昧粉紫）」。
> `ui_theme.py`（旧库 v3.x tkinter 主题）与 WebView2 版视觉自此脱钩，互不约束。

### 1.2 视觉令牌（炼香工坊 · 暗紫机身 + 暧昧粉紫）

一个光感原则：玫瑰粉 `#E8629A` 与紫 `#9B6BF0` 是主光源色，蜜金 `#E8B45A` 只留给「蜜语成品」语义。所有取值与 `styles.css` 的 `:root` 一一对应。

| 令牌 | 值 | 用途 |
|---|---|---|
| `--rose` / `--rose-hi` | `#E8629A` / `#F58BC0` | 暧昧粉（光源主色）：主按钮 / 当前步 / 焦点环 / 悬停粉边 |
| `--violet` / `--violet-soft` | `#9B6BF0` / `rgba(155,107,240,.18)` | 紫（第二光源）：导管 / info / 分段控件 / 语义辅助 |
| `--honey` / `--honey-soft` | `#E8B45A` / `rgba(232,180,90,.14)` | 蜜金（蜜语成品语义）：通过 / 已就位 / ok |
| `--bg` / `--bg-2` | `#1A1320` / `#221831` | 机身底（暖调深紫黑，非灰蓝） |
| `--surface` / `--surface-alt` | `#2A1E3A` / `#33254A` | 绒面紫玻璃卡片（渐变）/ 悬停与表头 |
| `--inset` | `#150F1E` | 内嵌凹槽：输入框 / 表格底 / 开关槽（配内阴影） |
| `--border` / `--edge` | `#3A2C4E` / `rgba(221,160,188,.22)` | 紫调边框 / 黄铜·玫瑰金描边（面板与卡片） |
| `--ink` / `--text` / `--text-sub` / `--text-mute` | `#F6EDF5` / `#E7DAEE` / `#BCAAC8` / `#9A8AA8` | 暖白带粉文字四级（mute 保证 ≥4.5:1 对比） |
| `--magenta` | `#E0577E` | 危险/阻断（销毁、还原、无方案） |
| 阴影体系 | `0 12px 30px rgba(0,0,0,.35)` + `inset 0 1px 0 rgba(255,255,255,.05)` 顶光 | 卡片静止/悬停浮起；`--rose-soft` 粉紫泛光用于主按钮与当前节点 |

**圆角**：控件 9px、卡片 14px、徽章/进度条/开关 全圆（999px）。
**字体（零联网，Windows 自带）**：展示体 `Georgia`（衬线，暧昧/编辑式）→ 等宽 `Cascadia Code`（铭牌/徽章/读数）→ 中文 `Microsoft YaHei`。
**字号**：正文 14px、页面标题 30px/700（衬线）、卡片标题 14px/700、等宽标注 10.5~11px（大字距全大写）。
**动效**：页面错落入场 `rise`（blur 交叉溶解）、卡片悬停泛粉边、进度条紫→粉 `shimmer` 液面、当前步节点 `simmer` 文火脉冲、
`logoGlow` 品牌标记明暗——全部 `@keyframes` + CSS，无 JS 业务耦合。

## 3. 技术选型（**待定，不影响本规格**）

本规格是技术中立的 HTML 原型，**下面任一条路线都能实现同一份版面**：

| 路线 | 真 WinUI 3 | 保现有 Python 资产 | 相对成本 |
|---|---|---|---|
| D tkinter 重排版面 | 否 | 全保 | 最低 |
| C Python + WebView2 仿 Fluent | 否（观感接近） | 全保 | 低 |
| B C# WinUI 3 壳 + Python 内核 IPC | 是 | 全保 | 中高 |
| A C# 全量重写 | 是 | **全部丢弃** | 最高（等同重做项目） |

**不推荐 A**：Python 侧沉淀（`engine_detector` 15 类规则、`kit_catalog` 10 个工具包、
`kit_installer` 下载/校验/部署、`rpgmaker_engine` 730 行字段白名单回写、两个护栏函数、
8 个翻译后端、`run_tests.py` 447 项回归）全部要重写，且重写期间旧版仍需维护。

> **决策建议**：先按原型跑一轮观感确认版面，再据此反推哪条路线值这个钱。

## 4. 验收清单（QA 视角）

老板确认版面后，实现完成按此清单逐条验：

**流程通顺性**
- [ ] 首次打开落在第 0 步；配好后再打开默认落在第 4 步（FR-37）
- [ ] 未连通 API 时，第 4 步主按钮禁用并给出原因（FR-38）
- [ ] 未来步骤不可点击；已完成步骤可回跳且下游不清零（FR-36）
- [ ] 顶栏不再出现任何业务按钮（§2 映射表逐条核对）

**按引擎分流**
- [ ] Unity 第 5 步不显示「应用到游戏」「还原原文」，且写明「不动游戏本体」
- [ ] RPG Maker 第 5 步显示备份位置、字段白名单与黑名单，「还原原文」为危险色
- [ ] TyranoScript 第 5 步不显示「应用到游戏」，列出 ≥2 条真实缺失原因
- [ ] 上述三情形分别真机验证一次写入/回写/导出

**诚实性**
- [ ] 未执行过的步骤，副标题显示「待执行」而非编造数值
- [ ] 工具清单的校验状态区分「已验证/仅查过 API」，与 `kit_catalog.verified` 一致
- [ ] 第 3 步明示约 1,000 条长对话缺口

**交互手感**
- [ ] 路径输入框可点击、可粘贴、回车跳转、双击弹选择器（不许退回 readonly）
- [ ] 表格双击内联编辑可用；14,679 条分页滚动不卡
- [ ] 每页只有一个主按钮，文案是具体动作词

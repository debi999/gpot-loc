## 逐条观察

### ① Unity（Starmaker 1.8E）

- 游戏目录名真的是 `Starmaker Story(1.8e` —— **缺右括号**。这是真实存在的目录名，
  不是脚本 bug。任何手工输入路径的场合都要注意反斜杠转义。
- 两个工具包都是 `skip_exists`：BepInEx 与 XUnity 已注入过，符合预期。
  缓存未命中（`cached=False`）也不影响——注入判定看的是游戏目录里的 marker 文件。
- **护栏拦下 87,509 条**，是扫描量（101,002）的 87%。这个比例很高但符合 Starmaker 的
  特征：大量 `.unity3d` 资源里的碎片与污染串。护栏没误伤的直接证据是抽检后的
  13,493 条都能对上译文表。
- 译文落点正确指向 `BepInEx\Translation\zh\Text\_AutoGeneratedTranslations.txt`。

### ② RPG Maker MV（一次性交易大师）

- 无注入工具，符合设计（MV 的文本直接写死在 `www\data\*.json` 里）。
- 译文落点 `_AutoGeneratedTranslations.txt` 在**游戏根目录**——这是 MV 的正确位置
  （由 `js\plugins` 里的翻译插件读取）。
- 8,102 条，护栏拦 0 条：MV 的 JSON 是结构化文本，碎片少。

### ③ 无方案引擎（Ren'Py · 青蛙的食谱）

- 识别出 `RenPy` 但**置信度仅 21%**，译文落点 `None`，提取 0 条。
- 这正是《开发计划》P2-2 待办里那条「引擎支持」的现状：**引擎被认出来了，但
  没有落点方案**。程序没有编一个假的落点出来糊弄人——这是诚实性 NFR-9 的正确表现，
  但也意味着 Ren'Py 用户现在拿不到汉化能力。
- **这就是 P2-2 的实证依据**：待办清单里列的 TyranoScript / WolfRPG / Kirikiri /
  NScripter 属于同一类问题。另外注意「~1,000 条长句对白未命中」的旧问题，
  本轮 Unity 侧未复现（13,493 条全部入表，无遗漏）。

## 待办影响

P2-2「引擎扩展」优先级**上调**：不是「锦上添花」，而是 Ren'Py / NScripter 这类游戏
在当前版本里**完全无法汉化**。建议下一轮优先接 Ren'Py（落点最清晰：`game/*.rpyc`
配套的 `translation` 字典），再依次 WolfRPG / NScripter。

## 技术栈决策矩阵（M1 输入）

| 路线 | 真 WinUI 3 | 保 Python 内核与回归 | 相对成本 | 主要风险 |
|---|---|---|---|---|
| D tkinter 重排版面 | 否 | 全保 | 最低 | 达不到 Fluent 观感 |
| C Python + WebView2 仿 Fluent | 否（观感接近） | 全保 | 低 | 新增第三方依赖；大表性能需实测 | **← 已选（2026-10-09）** |
| B C# WinUI 3 壳 + Python 内核 | 是 | 全保 | 中高 | 双语言双构建；沙箱无法自验编译；包体 ~100MB |
| A C# 全量重写 | 是 | **全丢** | 最高 | 等同重做项目 —— **已否决**（2026-10-09） |

**M1 验收口径**（哪条路线过线用哪条）：
- 14,679 行表格滚动/搜索/筛选流畅（交互响应 ≤200ms）
- 长任务进度推送与取消可用（翻译一跑几十分钟，不能假死）
- 构建可脚本化复现，产物能脱机运行
- 迭代节奏可接受（改一处到看到效果 ≤5 分钟）

## 已落地：C 路线最小原型（M1 产出）

老板 2026-10-09 拍板走 **C 方案**：Python 内核 + WebView2（Fluent 观感）。
入口 `src/main.py`，源码在 `src/`：

```
src/gpot/core/   业务内核：纯 Python 逻辑，零 UI / 零 HTTP 依赖（唯一真源）
src/gpot/api/    HTTP 桥：唯一把前端接到内核的地方（REST + JSON）
src/gpot/ui/     WebView2 宿主(pywebview) + 纯静态前端(index.html/app.js/styles.css)
src/tests/       内核解耦测试（只 import core，8 项全绿）
```

**解耦是这轮的核心约束**，三条硬规则（违反即耦合回归）：
1. `core/` 永不 import `api` 或 `ui` —— 内核可在无浏览器、无网络下独立运行（测试已证明）。
2. `api/` 只 import `core`，只出口 JSON —— 前端换技术栈（WebView2 / 真 WinUI3 壳 / tkinter）都不用动内核。
3. `ui/assets/` 是纯静态文件，只通过 `fetch('http://localhost:PORT/api/...')` 对话，自身无 Python。

接缝留痕：`core/` 里每个 `TODO(M2)` 标注处，就是旧库 `gui/` 真实逻辑迁入的位置
（`engine_detector` / `Translator`+`batch_fast` / `kit_catalog`+`kit_installer` / `rpgmaker_engine`）。
原型用 stub 复用真实数字把流程跑通，M2 只换函数体、不动契约。

**本轮（2026-10-09 续）两条流程细化已落地并实测：**
- **FR-49 翻译可选**：`pipeline._NEXT[3] = 5`（提取直接解锁保存），`translate.py`/`sink.py`/`extract.py`
  全部统一走 `pipeline.complete_step`，取消三处越权 `unlock_to`（步骤推进规则只在一处定义）。
- **FR-48 引擎锁死**：第 5 步引擎选择器默认锁定识别结果，选非当前引擎时保存按钮禁用；
  `/api/sink/apply` 二次校验（引擎不符返回 `400 engine_mismatch`）。
- 内核测试由 8 项增至 **9 项**（新增「提取后即可保存，无需翻译」）；API 层实测：提取后 `max=5`、
  选错引擎 apply 返回 400、正确引擎放行。

**已验证**：API 契约全端点通（state/providers/config/game/detect/deploy/extract/
translate(job 流式+取消)/sink 三形态/apply/verify/nav 锁）、静态首页与资源托管正常、
内核导航锁与解锁链正确、8 项内核测试通过。真机 WebView2 窗口渲染需在老板本机 `pip install -r requirements.txt` 后 `python main.py` 查看（沙箱无显示无法自验）。

## 快速认识

打开 G-POT 翻译器，你会看到**左侧一条流程轨、右侧一个工作区**。
无论上次用到了哪一步，**每次打开都从第 1 步（配置翻译服务）开始**；
上次的进度体现在左侧流程轨的解锁状态里 —— 已解锁的步骤直接点就能回去，不用重走。
左侧七个步骤就是你汉化一个游戏的全部动作；灰色的步骤要完成上一步才会解锁，
已经完成的步骤随时可以点回去重做。

窗口没有传统的标题栏——顶栏右侧就是最小化 / 最大化 / 关闭三键，顶栏空白处可以直接拖动窗口；
全程不会有黑色命令行窗口闪出。**当前版本号常显在状态栏右下角**（如 v0.4.3），
遇到问题时先核对这个号码，能最快判断跑的是不是新版。

**一次记住三件事就够了：**

1. 第 0~2 步是**一次性准备**，做完一个游戏就再也不用管；
2. 日常改译词只用 **第 4 步（改）→ 第 5 步（存）→ 重启游戏**；
3. 底部那条进度条，是当前正在跑的任务；其余时候它安静待着。

## 第 0 步 · 配置翻译服务

第一次打开会直接停在这一步。选一个翻译后端：

| 后端 | 适合谁 |
|---|---|
| 本地 Ollama | 电脑跑得动模型、想完全离线、不想花钱（推荐先试这个） |
| OpenAI 兼容 | 你有 DeepSeek / 通义 / 月之暗面等任意兼容端点的 Key |
| Google 免费 | 先体验、不在乎偶尔失败 |
| Claude / Gemini | 追求译文质量，按量付费 |
| DeepL / 百度 | 术语准确但游戏口吻一般，建议当兜底 |

选好填 Key（本地模型不用 Key），点 **测试连接** —— 显示连接正常才能点「保存并继续」。
连接失败时错误信息会直接告诉你原因：Key 不对 / 地址不通 / 模型名不存在。
测试成功后，可用的模型名会自动填进**模型下拉**，直接选一个即可（也可以随时点
**获取模型** 单独刷新列表，支持 Ollama 原生接口兜底）。下拉里列的是接口真实返回的
全部模型，不会因为当前选中了某个模型就只显示它一个。

列表里没有的模型（接口不返回、但你确实想调，比如某个未 pull 的 tag），
选下拉最末的**「自定义…」**，会展开一个输入框手输模型名 —— 手输的名字会照原样发出去。

模型下拉**永远只显示当前所选提供方的模型**：切换提供方卡片会清空上一家拉来的列表，
模型回落到该提供方的预设值；「获取模型」也是按当前所选提供方去拉
（Claude / Gemini 走各自的专用接口）。切了提供方记得重新点一次「获取模型」。

需要密钥的提供方（OpenAI 兼容 / DeepSeek / Claude / Gemini / DeepL）在 **API Key
没填**时点「获取模型」，会直接提示「请先填写再点『获取模型』」并聚焦到 Key 输入框，
不会发一次注定失败的请求。之前保存过密钥的话，重启后 Key 框显示为空是正常的
（密码框不回填），此时点「获取模型」仍会用已存的密钥照常拉取。

这一页还能配：

- **源/目标语言**（源语言默认自动检测）；
- **并发数 / 请求间隔**——本地模型默认 3 并发就够，云端可调高，翻译时真实生效；
- **翻译提示词…**——给 AI 的翻译指导（口吻、术语、禁区）。留空用内置默认；
  改过之后翻译缓存会整体失效，下次翻译全部按新提示词来。用「恢复默认」一键还原。

用本地 Ollama 时，测试连接成功会**自动把当前地址/模型同步进游戏的实时翻译配置**
（`server_config.ini`），重启游戏内翻译服务即生效——不用再手动改。

### 设置都在齿轮里（右上角）

第 0 步之外还有几项设置，统统收在右上角**齿轮**里，点开是一张下拉菜单：

| 菜单项 | 作用 |
|---|---|
| 翻译提示词… | 打开提示词编辑弹窗（同第 0 步那个按钮） |
| 校验注入工具 | 打开弹窗，**按当前引擎逐项核对**（详见下节） |
| 运行日志 | **只读**诊断信息：版本、游戏目录、识别引擎、工具状态、词典条数（已译/未译/损坏字符）、词典是否被外部改过、当前流程位置、每一步的真实状态 |
| 重置流程 | 回到第 0 步重新开始（**译文词典不会删除**） |

明暗切换在**标题栏右上角**（太阳图标），不在这个菜单里。

菜单底部会显示当前版本号（如 `v0.5.5`）。连不上后端时会明说「版本未知（未连接后端）」——
不会留下 `v—` 这种看不懂的东西（界面各处同理：拿不到真值就写人话，不摆哑谜占位符）。点菜单外任意空白处即收起，不挡操作。

### 校验注入工具弹窗（按引擎逐项核对）

点「校验注入工具」会打开一张核对表 —— **不是一句话结论**，而是把当前引擎需要的东西逐项摆出来：

- **弹窗头部**：识别到的引擎、**译文最终写到哪个文件**（绝对路径）、该引擎的译文生效方式、方案备注；
- **每个工具一行**：工具名 + 状态徽章（`已就位` / `待部署` / `可选 · 未选装` / `无可靠包`）+
  放在哪 + **靠哪个文件判定它已经就位** + 下载缓存有没有 + 缺了会有什么后果。

举例（Unity / Starmaker Story）：

```
Unity (Mono) · 工具齐备 · 共 2 项
译文落点：…\Starmaker 1.8E\BepInEx\Translation\zh\Text\_AutoGeneratedTranslations.txt
XUnity.AutoTranslator 自动翻译词典，游戏运行时直接读它。

BepInEx 5.4.23.5 (Windows x64)                        [已就位]
  落点：…\Starmaker 1.8E
  判定文件：…\Starmaker 1.8E\BepInEx\core\BepInEx.Preloader.dll
  下载缓存为空（部署时会现拉）
  已安装（BepInEx/core/BepInEx.Preloader.dll 已存在；加 --force 覆盖）
```

**这是只读检查**，不会下载也不会写盘。想真正部署请回第 2 步点「部署注入工具」。

**工具包存哪、怎么省流量**：下载下来的包保存在**程序文件夹**的 `toolcache\` 里（不在游戏目录）。
想离线部署或省流量，可以提前把校验界面列出的包（按上面的文件名）放进这个文件夹，
部署时校验通过就直接安装、完全不联网；文件夹里没有对应引擎的工具才走下载
（自动多源尝试，GitHub 直连慢会切镜像）。

**第 2 步会先校验再问你要不要下载（v0.5.8）**：识别引擎完成后**立即自动校验**工具，
表格直接摆出每项真实状态——「已注入游戏」/「已缓存·待注入」（程序目录已有母本，无需下载）/
「需下载」；主按钮文案跟着缺项自动变（全就位 → 主按钮是「进入下一步」，旁边「重新校验」
降级为次要按钮、只重跑校验不部署（v0.6.4）；缺项全有缓存 →「部署到游戏（无需下载）」；
有缺缓存的 →「下载并部署（缺 N 项，约 N MB）」）。
工具母本恒存程序目录 `toolcache\`，点部署时才注入游戏目录，缓存命中不重复下载。

**键盘快捷键（v0.5.9 新增）**

| 快捷键 | 作用 |
|---|---|
| `Alt+1` ~ `Alt+7` | 直接跳到第 1 ~ 7 步 |
| `Alt+D` | 切换明暗主题 |
| `Ctrl+F` | 跳到校对页搜索框（焦点不在输入框时生效） |
| `Ctrl+Shift+S` | 保存并应用到游戏 |
| `Esc` | 关闭当前最上层弹窗 |

> 焦点在输入框里时，除 `Esc` 外快捷键一律让位（打字不会误跳步）。
> 键盘 Tab 第一下会弹出「跳到主内容」链接；所有焦点位置都有高对比描边。

**窗口缩放（v0.6.0 新增）**：窗口是无边框的，现在把鼠标移到窗口**四边或四角**
会出现双向缩放光标，拖动即可改窗口大小（走 Windows 原生机制，拖出窗口外也不丢事件）。
如果你用的是 `--open-browser` 浏览器模式，缩放请用浏览器窗口自己的边缘。

如果该引擎用**原生机制**（如 RPG Maker MV/MZ，文本直接写死在数据文件里），弹窗会如实说明
「没有需要部署的注入工具」并给出原因，不会给你编一个假的工具出来。

## 第 1 步 · 选择游戏目录

选游戏的**根目录**：就是放游戏 .exe 的那一层，不是它的上级也不是子文件夹。
点「浏览」弹出的是 Windows 现代风格的选择对话框（带地址栏和「新建文件夹」按钮）；
也可以直接把路径粘贴进输入框回车，或从「最近使用」里点以前用过的游戏。

如果这个游戏以前翻过，这里会告诉你已积累多少条译文 —— 放心，继续操作只做增量，不覆盖。

## 第 2 步 · 识别引擎与部署注入工具

点一下就会扫游戏目录，告诉你这是什么引擎做的（比如 Unity / RPG Maker / 吉里吉里），
并列出**证据**（哪些文件暴露了身份）。置信度低时你可以手动改选。

> 省事提示：第 1 步选好游戏目录后，引擎通常会**自动识别好**并直接放开这一步。
> 如果没有（比如目录选到了外层），点一下识别即可。

然后是**一次性部署**这个引擎需要的翻译工具。三个预期，遇到哪种都正常：

- **Unity（Starmaker Story 就是这类）**：装 BepInEx + XUnity.AutoTranslator。
  游戏本体一个字节都不改，随时可整体撤销。
- **RPG Maker MV/MZ**：这类游戏文本写死在数据文件里，没有"运行时替换"的口子。
  第 5 步会直接改数据文件 —— 执行前程序自动备份，坏了能一键还原。
- **其它引擎**：清单里如果某工具显示"没有可靠方案"，说明我们没找到能自动部署的稳定包，
  这一步会如实告诉你缺什么、可以用什么替代（如 Textractor），不会塞一个跑不通的假链接给你。

## 第 3 步 · 提取待翻译文本

**不用启动游戏**。点「开始提取」，程序直接扫游戏资源把原文捞出来。
默认选项就是推荐选项；护栏开关后面的数字是上一轮的真实拦截记录，看一眼就有底。

提取结束会显示四个数：新增 / 已存在跳过 / 护栏拦截 / 在表总数。
如果提示「约 1,000 条长段对话拿不到」，是当前提取方式的已知边界，不是你操作错了。
提取完成后第 4、5 步同时解锁，表格里能直接看到已提取的全部条目。

> **「提取未执行」是什么意思**：说明前置条件没满足（最常见是还没选对游戏目录）。
> 这时程序**不会**假装扫了一遍报「新增 0 条」，而是直接告诉你缺哪一步。
> 回第 1 步选对游戏目录 → 第 2 步确认引擎 → 再回来提取即可。

### 步骤之间不会「跳着走」

左侧流程是**带闸门**的：没做前置步骤，后面的步骤点不动，状态栏会告诉你**具体缺哪一步**
（比如「先完成『第 2 步·识别引擎』」），而不是笼统一句「还没解锁」。
这是刻意的——早前版本能一路点到第 4 步，结果第 2 步形同虚设、提取扫不到东西，表格一片空白。

另外：**中途关掉再打开**，程序会回读游戏目录和译文词典确认它们还在（词典和引擎照常恢复，
第 4 步表格不会空白），解锁进度照旧保留 —— 但**落点每次都是第 1 步**，去哪一步由你点。
如果游戏被移动或删了，它会诚实地把解锁进度收回去，而不是停在一个空页面上。

## 第 4 步 · 翻译与人工校对

主要工作量在这一步，也是最像"编辑器"的一页：

- 上半部分：进度指标 + **翻译未译条目** 主按钮（下拉可选：仅未翻译 / 当前筛选 / **翻译勾选行** / 全部 / 仅重试失败）；
- 中间：表格。**双击任何一行的译文格就能改**——回车或点别处保存（立即写盘），
  Esc 取消；清空译文会自动标回「未翻译」；行首勾选框可挑任意几行来翻（跨页保留）；
- 顶部搜索框、状态筛选（全部/未翻译/英文残留/已翻译）都会实时过滤；
  **点表头**（状态/原文/译文）可排序，再点一次反向；
- 表格底部是**真分页条**：可以翻页，也可以选每页显示 50 / 100 / 200 / 500 条；
- **右键任意行**：复制原文 / 复制译文 / 查看全文（长句弹窗看完整内容）/ 清空译文 / 删除条目；
- 右上幽灵按钮：导入导出 CSV、**导入 TXT**（支持 `原文=译文`、Tab 分隔、纯原文三种格式自动识别）、查找替换、清理重复 —— 平时不用管；
- 词典文件若被游戏或其它编辑器在外部改写，这一页顶部会出现**警示条**，点「重新载入」即可拉到最新内容。

**机器跑完之后，请务必人工过一遍未翻译和英文残留**：口吻、称谓、双关这些，翻错比没翻更伤。

放心按钮：批量翻译只处理「未翻译」和「当前筛选」的条目，**已经翻好的不会被覆盖**。

> **翻译是可选的**：从 v4.0 起，第 4 步不再是进入保存的硬门槛。第 3 步（提取）完成后，第 4 步和第 5 步会**同时解锁**——老条目已译、或你只想先验证「提取 → 写入」链路时，可以跳过翻译、直接进第 5 步保存。没翻的条目照样随工作副本落盘。

## 第 5 步 · 保存并应用到游戏

这一步长什么样由**引擎**决定（第 2 步识别的结果）：

> ⚠️ **第 5 步锁定在第 2 步识别出的引擎上。** 引擎选择器只是用来预览其它管线的落地形态——一旦切到非当前引擎，「保存并写入」按钮会变灰并提示锁定原因，点回当前引擎即解锁。这是为防止把 A 引擎的写入逻辑（如 RPG Maker 回写）套到 B 引擎游戏上导致数据损坏。

- **Unity 类**：按钮是「保存并写入词典」。词典写在 BepInEx 的翻译目录里，
  **重启游戏就能看到**，游戏文件没动过。
- **RPG Maker 类**：按钮是「备份原文并回写游戏」。这一步会改 `www/data/*.json`，
  所以按钮旁有红色的「还原原文」；写之前会自动留一个时间戳备份。
  如果回写后出现立绘丢失/花屏，点「还原原文」回到原样，再来找我们看是哪个字段的问题。
- **Coming soon**：暂无自动方案的引擎显示为「Coming soon」，页面只有「敬请期待」
  一行——译文不会丢，存在本地草稿里，后续版本会补方案。

## 第 6 步 · 启动验证

点「启动游戏验证」会**真的帮你启动游戏**（程序自动找到游戏主程序），
进游戏看效果。点「打开译文目录」可以直接跳到译文所在文件夹。
程序这边会先自检三项：文件在不在、条目数对不对、格式合不合法。
Unity 记住一句话：**改完词典要重启游戏才生效**，游戏开着不行。

## 常见问题

**Q：翻译跑了几分钟就报错一批？**
看第 4 步「失败」计数，点「仅重试失败」。反复失败通常是 Key 限速或余额不足，换后端或降低并发。

**Q：识别出的引擎置信度很低？**
说明目录里证据不足。先确认第 1 步选的是根目录；还低就手动改选，或把游戏名发给我们补规则。

**Q：游戏里还是英文？**
Unity 类按顺序查：① 第 5 步保存了吗 ② 游戏重启了吗 ③ 游戏语言设置是中文吗
（XUnity 按 `Language` 目录读，`zh-CN`/`zh` 都支持）。

**Q：想彻底回到没翻译的状态？**
Unity 类：删掉 BepInEx/Translation/zh-CN 目录即可（或整个卸载 BepInEx）。
RPG Maker 类：第 6 步点「还原原文」。

**Q：换了个新游戏？**
左侧点「1 选择游戏」换个目录，从第 1 步走到头就行。前一个游戏的所有译文不会丢。

**Q：第 5 步的「保存并写入」按钮是灰的，点不动？**
你大概率在引擎选择器里切到了非当前游戏引擎。第 5 步默认锁定在第 2 步识别出的引擎，切到别的只用于预览形态，保存会被禁用。点回上方识别出的那个引擎即可解锁。

**Q：双击了启动 bat，出来的还是旧界面 / 旧版本？**
先看状态栏右下角的版本号。如果不是最新版，说明有一个旧实例还挂在后台——把它关掉再双击一次即可。程序现在会自动识别旧版本实例并另起新版，但同端口被旧进程占着时最干净的办法还是先关旧窗口。

**Q：我想先不翻译、只验证"提取 → 写入"链路，可以吗？**
可以。第 3 步提取完后第 4、5 步同时解锁，直接进第 5 步保存即可；没翻译的条目会随工作副本一起落盘，之后想翻了再回第 4 步补。

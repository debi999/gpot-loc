# G-POT 翻译器 · 使用手册

> 适用版本 v4.0（七步流水线版面） · 2026-10-09 · 增补 2026-10-10（v0.4.1~v0.4.3 实测反馈）
>
> ⚠️ 本手册描述 **v4.0 目标行为**。当前可下载的稳定版仍是 v3.x（旧界面），
> 新版发布后本文即为正式说明书 —— 两版差异见文末「从 v3.x 升级」。

## 快速认识

打开 G-POT 翻译器，你会看到**左侧一条流程轨、右侧一个工作区**。
左侧七个步骤就是你汉化一个游戏的全部动作；灰色的步骤要完成上一步才会解锁，
已经完成的步骤随时可以点回去重做。

窗口没有传统的标题栏——顶栏右侧就是最小化 / 最大化 / 关闭三键，顶栏空白处可以直接拖动窗口；
全程不会有黑色命令行窗口闪出。**当前版本号常显在状态栏右下角**（如 v0.4.3），
遇到问题时先核对这个号码，能最快判断跑的是不是新版。

**一次记住三件事就够了：**

1. 第 0~2 步是**一次性准备**，做完一个游戏就再也不用管；
2. 日常改译词只用 **第 4 步（改）→ 第 5 步（存）→ 重启游戏**；
3. 底部那条进度条，是当前正在跑的任务；其余时候它安静待着。

## 第 0 步 · 配置翻译服务

第一次打开会直接停在这一步。选一个翻译后端：

| 后端 | 适合谁 |
|---|---|
| 本地 Ollama | 电脑跑得动模型、想完全离线、不想花钱（推荐先试这个） |
| OpenAI 兼容 | 你有 DeepSeek / 通义 / 月之暗面等任意兼容端点的 Key |
| Google 免费 | 先体验、不在乎偶尔失败 |
| Claude / Gemini | 追求译文质量，按量付费 |
| DeepL / 百度 | 术语准确但游戏口吻一般，建议当兜底 |

选好填 Key（本地模型不用 Key），点 **测试连接** —— 显示连接正常才能点「保存并继续」。
连接失败时错误信息会直接告诉你原因：Key 不对 / 地址不通 / 模型名不存在。
测试成功后，可用的模型名会自动填进下拉建议，直接选一个即可。

## 第 1 步 · 选择游戏目录

选游戏的**根目录**：就是放游戏 .exe 的那一层，不是它的上级也不是子文件夹。
点「浏览」弹出的是 Windows 现代风格的选择对话框（带地址栏和「新建文件夹」按钮）；
也可以直接把路径粘贴进输入框回车，或从「最近使用」里点以前用过的游戏。

如果这个游戏以前翻过，这里会告诉你已积累多少条译文 —— 放心，继续操作只做增量，不覆盖。

## 第 2 步 · 识别引擎并部署注入工具

点一下就会扫游戏目录，告诉你这是什么引擎做的（比如 Unity / RPG Maker / 吉里吉里），
并列出**证据**（哪些文件暴露了身份）。置信度低时你可以手动改选。

然后是**一次性部署**这个引擎需要的翻译工具。三个预期，遇到哪种都正常：

- **Unity（Starmaker Story 就是这类）**：装 BepInEx + XUnity.AutoTranslator。
  游戏本体一个字节都不改，随时可整体撤销。
- **RPG Maker MV/MZ**：这类游戏文本写死在数据文件里，没有"运行时替换"的口子。
  第 5 步会直接改数据文件 —— 执行前程序自动备份，坏了能一键还原。
- **其它引擎**：清单里如果某工具显示"没有可靠方案"，说明我们没找到能自动部署的稳定包，
  这一步会如实告诉你缺什么、可以用什么替代（如 Textractor），不会塞一个跑不通的假链接给你。

## 第 3 步 · 提取待翻译文本

**不用启动游戏**。点「开始提取」，程序直接扫游戏资源把原文捞出来。
默认选项就是推荐选项；护栏开关后面的数字是上一轮的真实拦截记录，看一眼就有底。

提取结束会显示四个数：新增 / 已存在跳过 / 护栏拦截 / 在表总数。
如果提示「约 1,000 条长段对话拿不到」，是当前提取方式的已知边界，不是你操作错了。
提取完成后第 4、5 步同时解锁，表格里能直接看到已提取的全部条目。

## 第 4 步 · 翻译与人工校对

主要工作量在这一步，也是最像"编辑器"的一页：

- 上半部分：进度指标 + **翻译未译条目** 主按钮（下拉可选：仅未翻译 / 当前筛选 / 全部 / 仅重试失败）；
- 中间：表格。**双击任何一行的译文格就能改**——回车或点别处保存（立即写盘），
  Esc 取消；清空译文会自动标回「未翻译」；
- 顶部搜索框、状态筛选（全部/未翻译/英文残留/已翻译）都会实时过滤；
- 表格底部是**真分页条**：可以翻页，也可以选每页显示 50 / 100 / 200 / 500 条；
- 右上幽灵按钮：导入导出 CSV、查找替换、清理重复 —— 平时不用管。

**机器跑完之后，请务必人工过一遍未翻译和英文残留**：口吻、称谓、双关这些，翻错比没翻更伤。

放心按钮：批量翻译只处理「未翻译」和「当前筛选」的条目，**已经翻好的不会被覆盖**。

> **翻译是可选的**：从 v4.0 起，第 4 步不再是进入保存的硬门槛。第 3 步（提取）完成后，第 4 步和第 5 步会**同时解锁**——老条目已译、或你只想先验证「提取 → 写入」链路时，可以跳过翻译、直接进第 5 步保存。没翻的条目照样随工作副本落盘。

## 第 5 步 · 保存并应用到游戏

这一步长什么样由**引擎**决定（第 2 步识别的结果）：

> ⚠️ **第 5 步锁定在第 2 步识别出的引擎上。** 引擎选择器只是用来预览其它管线的落地形态——一旦切到非当前引擎，「保存并写入」按钮会变灰并提示锁定原因，点回当前引擎即解锁。这是为防止把 A 引擎的写入逻辑（如 RPG Maker 回写）套到 B 引擎游戏上导致数据损坏。

- **Unity 类**：按钮是「保存并写入词典」。词典写在 BepInEx 的翻译目录里，
  **重启游戏就能看到**，游戏文件没动过。
- **RPG Maker 类**：按钮是「备份原文并回写游戏」。这一步会改 `www/data/*.json`，
  所以按钮旁有红色的「还原原文」；写之前会自动留一个时间戳备份。
  如果回写后出现立绘丢失/花屏，点「还原原文」回到原样，再来找我们看是哪个字段的问题。
- **Coming soon**：暂无自动方案的引擎显示为「Coming soon」，页面只有「敬请期待」
  一行——译文不会丢，存在本地草稿里，后续版本会补方案。

## 第 6 步 · 启动验证

点「启动游戏验证」会**真的帮你启动游戏**（程序自动找到游戏主程序），
进游戏看效果。点「打开译文目录」可以直接跳到译文所在文件夹。
程序这边会先自检三项：文件在不在、条目数对不对、格式合不合法。
Unity 记住一句话：**改完词典要重启游戏才生效**，游戏开着不行。

## 常见问题

**Q：翻译跑了几分钟就报错一批？**
看第 4 步「失败」计数，点「仅重试失败」。反复失败通常是 Key 限速或余额不足，换后端或降低并发。

**Q：识别出的引擎置信度很低？**
说明目录里证据不足。先确认第 1 步选的是根目录；还低就手动改选，或把游戏名发给我们补规则。

**Q：游戏里还是英文？**
Unity 类按顺序查：① 第 5 步保存了吗 ② 游戏重启了吗 ③ 游戏语言设置是中文吗
（XUnity 按 `Language` 目录读，`zh-CN`/`zh` 都支持）。

**Q：想彻底回到没翻译的状态？**
Unity 类：删掉 BepInEx/Translation/zh-CN 目录即可（或整个卸载 BepInEx）。
RPG Maker 类：第 6 步点「还原原文」。

**Q：换了个新游戏？**
左侧点「1 选择游戏」换个目录，从第 1 步走到头就行。前一个游戏的所有译文不会丢。

**Q：第 5 步的「保存并写入」按钮是灰的，点不动？**
你大概率在引擎选择器里切到了非当前游戏引擎。第 5 步默认锁定在第 2 步识别出的引擎，切到别的只用于预览形态，保存会被禁用。点回上方识别出的那个引擎即可解锁。

**Q：双击了启动 bat，出来的还是旧界面 / 旧版本？**
先看状态栏右下角的版本号。如果不是最新版，说明有一个旧实例还挂在后台——把它关掉再双击一次即可。程序现在会自动识别旧版本实例并另起新版，但同端口被旧进程占着时最干净的办法还是先关旧窗口。

**Q：我想先不翻译、只验证"提取 → 写入"链路，可以吗？**
可以。第 3 步提取完后第 4、5 步同时解锁，直接进第 5 步保存即可；没翻译的条目会随工作副本一起落盘，之后想翻了再回第 4 步补。

## 从 v3.x 升级

- 配置（`config.ini`、`server_config.ini`）和翻译工作副本完全兼容，直接沿用；
- 旧界面里的按钮在新界面的位置见下表（其余没变的不再列）：

| 旧位置 | 新位置 |
|---|---|
| ⚙ 设置里的翻译服务 | 第 0 步 |
| 顶栏「识别引擎」 | 第 2 步 |
| 顶栏「注入工具」 | 第 2 步（前移） |
| 顶栏「提取」 | 第 3 步 |
| 顶栏「翻译 ▾」 | 第 4 步主按钮 |
| 顶栏「保存」 | 第 5 步主按钮 |
| 顶栏「应用到游戏」 | 第 5 步（仅需要的引擎显示） |
| 工具条「还原原文」 | 第 5 步 / 第 6 步（仅需要的引擎显示） |

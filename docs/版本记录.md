# 版本记录（版本号单一真源）

> **顺序铁律：升版先在本文件写一行 → 再改代码 → 最后回填 `APP_VERSION`。**
>
> 为什么立这条（2026-10-13 老板诊断）：以前是改完代码顺手改版本号、文档事后补，
> 文档永远是**事后追认**，必然对不上。实证：真源 `0.6.5` 时 docs 已写 `0.6.7`、
> tests 已写 `0.6.8`；后来把代码升到 `0.6.8` 追平，红灯自己灭了 ——
> 校验规则因此失去意义（它只证明了「代码追上了文档」，没证明文档是对的）。
>
> 文档先行 = 先定「这个版本要做什么、叫什么」，代码再跟随。PM 视角的规格先行。
>
> **机械检查**：`tools/rule_check.py` R3 取本文件「## 当前版本」区的版本号，
> 与 `src/gpot/api/server.py::APP_VERSION` 双向比对，不一致即 FAIL。
> 文档里其他位置的 `vX.Y.Z`（历史叙述、FR 编号附注）**一律不参与判定**。

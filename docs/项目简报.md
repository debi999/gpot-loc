## 一、产品定位与风格

### 1.1 它是什么

**G-POT 翻译器**（英文 G-POT Loc，repo `gpot-loc`）—— 一台 Windows 桌面应用，
把**生肉独立游戏**变成能玩的**中文版**：识别引擎 → 提取文本 → 机器翻译 → 人工校对 → 按引擎机制写回游戏并生效。

> Slogan：**把生肉熬成蜜语。/ Localize the desire.**
> 流程标语：**Hook · Extract · Translate.**

一句话给外行：以前汉化一个游戏要会用反编译工具、改十六进制、写脚本；现在它把这一切变成 7 步向导，点按钮就行。

### 1.2 给谁用

| 用户 | 画像 | 对界面的要求 |
|---|---|---|
| **主用户（老板本人）** | PM + 测试主管，懂游戏懂流程，**不写代码** | 「我在哪 / 该点哪 / 干完会怎样 / 出事怎么办」四问必须在 3 秒内有答案 |
| 次用户 | 同类玩家-汉化爱好者 | 同上，零术语门槛 |

不是给开发者的工具箱，不给命令行，不暴露内部概念（引擎细节只在"证据 chip"里露脸）。

### 1.3 整体感觉：炼香工坊的配方台账

**三个词：安静、可靠、编辑式。**

- **安静**：低密度（NFR-12：每屏 ≤1 行导语），无渐变卡堆叠、无光晕脉冲、无等宽指标网格——四套"AI 模板味"配方全部禁用。
- **可靠**：像一本实验台账——细线分区、方形铭文标签、等宽数字带，每个数字都有出处（实测值，不是装饰）。
- **编辑式**：衬线展示体标题（Georgia）+ 等宽标注 + 玫瑰粉主色，像一本认真排印的手工志，不像 SaaS 后台。

**结构语言 = 配方台账**：`.sec` 台账分区（158px 左铭牌 + 右内容非对称网格）、`.strip` 数字带、`.lrow` 台账行、`.tag` 方形铭文、全平面 3px 圆角、容器零渐变零辉光。
**视觉验收判据：截图转灰度后，仍能一眼看出每屏唯一的主按钮。**

## 二、需求清单

### 2.1 要什么（做对的事）

| # | 需求 | 依据 |
|---|---|---|
| 1 | **七步柔性流程**：0 配置服务 → 1 选游戏 → 2 识别引擎+部署工具 → 3 提取 → 4 翻译+校对 → 5 保存并应用 → 6 启动验证；可回跳不可跳前，回跳不清零下游 | FR-36/49 |
| 2 | **每屏唯一主按钮**，文案是具体动作词；禁用必带「为什么 + 怎么解锁」tooltip | FR-46 |
| 3 | **第 2 步主按钮状态机移交**：识别引擎 → 部署工具，任一时刻只有一个主按钮 | 界面简报 §5.3 |
| 4 | **按引擎分流第 5 步（三情形变脸）**：A 运行时替换（保存即生效）/ B 必须回写（RPG Maker：先备份再回写，白名单+黑名单 8 项）/ C 无自动方案（导出 CSV + 真实缺失原因 + 退路建议） | FR-44/48 |
| 5 | **诚实呈现**：未执行写「待执行」不编 0；工具校验区分「已验证 / 仅查过 API」；第 3 步常驻提示 ~1,000 条长对话缺口；状态栏写完成时态结果 | NFR-9/10, FR-41/47 |
| 6 | **高频屏（第 4 步）最低摩擦**：改一句台词 = 第 4 步进 → 改 → 第 5 步出；批量卡压成一行，表格吃满剩余高度 | FR-43 |
| 7 | **低密度文案纪律**：每屏 1 行导语、每卡 1 行副标题、解释设计的话只进文档不进界面 | NFR-12 |
| 8 | **三层解耦（工程铁律）**：core 纯逻辑零 UI 依赖 / api 只出口 JSON / ui 只 fetch——换 UI 栈不动内核 | 技术栈 C 路线 |
| 9 | **明暗双主题**：暗色默认（深夜工坊），亮色备选（白粉纸面），标题栏一键切换 + localStorage 记忆 | v4.0 已实施 |

### 2.2 避免什么（不做的事）

| # | 禁区 | 原因 |
|---|---|---|
| 1 | **四套模板配方**：渐变圆角卡堆叠 / auto-fit 等宽指标网格 / 999px 药丸徽章 / 每屏同骨架 | 前三稿视觉被否的根因：换皮不换结构，越换越像模板 |
| 2 | **一屏两个主按钮**、泛化的「保存/确定」按钮 | FR-46；灰度下分不出主次 |
| 3 | **颜色承载信息**：主次、状态不许只靠颜色区分，必须形状/图标/文字前缀兜底 | 无障碍 + 灰度判据 |
| 4 | **提案语言进界面**：「灰色的步骤会解锁」「重看一遍流程」「本来就不需要」类解释设计/演示残留的话 | NFR-12，已实证清除 |
| 5 | **隐喻动词做功能文案**：不用「萃取/炼制/封存」，用「提取/保存/应用」；隐喻只留在视觉层与代码注释 | 老板 2026-10-09 纠偏 |
| 6 | **伪数据**：占位 0、编造进度、统一显示「已验证」、空泛形容词（"智能高效"） | 数据真确 > 输出好看 |
| 7 | **readonly 路径框**、只许选不许粘贴输入 | 第 1 步实操反例 |
| 8 | **改游戏本体一个字节**（未经第 5 步 B 情形备份流程）；A/C 情形绝不出现「应用到游戏」「还原原文」按钮 | 红线 FR-44 |

## 三、品牌色

**主色：玫瑰粉（Rose）。** 一套色板、两副面孔（暗 / 亮），以下全部取自已实施的 CSS 变量（`ui-prototype-v2.html` / `src/gpot/ui/assets/styles.css`），是唯一真源。

### 3.1 色板

| 令牌 | 暗色（默认） | 亮色 | 语义（**每色 ≤2 个用途，色彩预算**） |
|---|---|---|---|
| `--rose` 主色 | `#E8629A` | `#E05590` | **主按钮 + 导航轨当前步**（仅此两处） |
| `--rose-hi` 高光 | `#F58BC0` | `#C93B7C` | 主按钮 hover/按下 |
| `--violet` 紫 | `#9B6BF0` | `#8A55E8` | **信息 / 导管 / 进度条** |
| `--honey` 蜜金 | `#E8B45A` | `#B07A1E` | **通过 / 成品**（校验通过、任务完成） |
| `--magenta` 品红 | `#E0577E` | `#D63A66` | **警告 + 危险**（形状区分：warn 空心 / danger 实底） |

### 3.2 中性色（机身与文字）

| 令牌 | 暗色 | 亮色 | 用途 |
|---|---|---|---|
| `--bg` | `#1A1320` | `#FBF5F8` | 机身底 |
| `--surface` | `#241A32` | `#FFFFFF` | 台账卡面 |
| `--inset` | `#150F1E` | `#F7EBF1` | 表格/输入内嵌区 |
| `--border` / `--hairline` | `#3A2C4E` / 62% 透明 | `#E4CCD9` / `#F0DFE9` | 分区线 / 细线 |
| `--ink` → `--text-mute` | `#F6EDF5` / `#E7DAEE` / `#BCAAC8` / `#9A8AA8` | `#2B1B27` / `#4A3546` / `#6E586A` / `#9C8696` | 标题 / 正文 / 次要 / 弱化 |

### 3.3 用色规则

1. 玫瑰粉是**稀缺资源**：一屏只出现在主按钮和当前步节点，出现第二次就是违规。
2. 紫永远不表达"完成"，蜜金永远不表达"进行中"——跨主题语义恒定。
3. 警告 vs 危险靠**形状**（空心/实底），不靠色相微差。
4. 主题切换只换变量值，不换语义；`html[data-theme="light"]` 一层变量块实现，暗色为默认（无属性即暗）。

## 五、验收一句话

**灰度截图里：每屏只剩一个实心主按钮、导航轨告诉你在这、状态栏告诉你干完了什么、数字带里的每个数都有出处——做到这四条，骨架合格；玫瑰粉只出现在两处、没有任何渐变卡和药丸——视觉合格。**

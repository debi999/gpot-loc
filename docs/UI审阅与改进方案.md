## 3. P2 · 视觉级问题（骨架定稿后做）

### 3.1 ★ 粉色语义过载（自查与盲评共识，最优先）

**现状**：玫瑰粉同时承担了 **7 种语义**——主按钮、当前步、已完成步、选中态、游戏头像、进度条、警告色（`--warn:var(--rose)`）。结果：粉不再是"主操作"的信号，**转灰度后主次不可辨**（这正是三稿都像模板的底层原因之一）。警告与主操作同色，是直接的语义冲突。

**方案 · 色彩预算表**（每色语义数 ≤2）：

| 色 | 现承担 | 收敛后只留 |
|---|---|---|
| 玫瑰粉 `--rose` | 主按钮/当前步/已完成/选中/头像/进度/警告 | **主按钮 + 当前步**（仅 2 个） |
| 紫 `--violet` | 导管/信息/第二光源 | 信息类 + 导航导管 |
| 蜜金 `--honey` | 通过/已就位（纪律良好，盲评确认） | 维持不变 |
| 品红 `--magenta` | 危险 | **+ 警告**（`--warn` 从 rose 改指 magenta 系） |
| （新增中性） | — | **已完成步**：去饱和紫灰 + ✓，把"完成"从光源位上撤下来 |

**判断依据**：完成后"发光"没有信息量——用户不需要被已完成的事持续吸引注意力；把光让给"当前该做的事"。
